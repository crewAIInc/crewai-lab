01 / 15

why flows

Flows decide. Agents phrase.

  • Event-driven orchestration — steps fire when upstream steps complete, not on a model's whim.
  • Mix code and LLMs freely — plain Python, direct LLM calls, single Agents, or whole Crews in one pipeline.
  • Business rules live in code — routing, priority, and validation are reviewable and testable.
  • Typed state throughout — every step reads and writes one Pydantic model.

If a decision must be right every time, put it in the Flow — not the prompt.

04 / 15

the flow toolbox

Core decorators, one glance

@start()

Entry point. Runs on kickoff(); several @start methods run in parallel.

@listen(step)

Chain. Fires when a step (or "label") completes; receives its return value.

@router(step)

Branch. Returns a label string; each @listen("LABEL") starts a different path.

or_() · and_()

Fan-in. or_ fires on the first upstream step, and_ waits for all of them.

@persist

Durability. Saves state (SQLite) after steps; resume or fork a run by its state id.

@human_feedback(…)

Approval gate. Pauses for a reviewer; their reply maps onto emit labels.

methods ❯ kickoff(inputs=…) plot() self.state usage_metrics memory & resume — next slide ▸
05 / 15

built-in flow methods

Memory, resume, streaming — on self

self.remember(content, …)

Memory write. Store facts with scope (e.g. /accounts/acme/…), categories, and importance — durable across runs.

self.recall(query, …)

Memory read. Semantic search within a scope, capped by limit. Treat results as context, never authority.

self.extract_memories(text)

Distill. Turns raw text into a list of discrete facts ready to remember().

resume(feedback)

Continue after a pause. Picks a flow back up at its @human_feedback gate; pending_feedback tells you it's waiting.

stream_events() · kickoff_async()

Streaming & async. Consume execution as ordered frames, or run the graph on an event loop.

fork() · from_checkpoint()

Branch & restore. Rebuild a flow from a checkpoint, or fork a new execution branch from one.

Memory is scoped on purpose: /accounts/<slug>/… keeps tenants separate — same idea as the MCP allowlists.

deterministic routing

Policy is code you can unit-test

triage — no LLM involved
@listen(normalize)
def triage(self) -> str:
    if self.state.case.severity == "critical":
        self.state.queue = "incident_response"
        self.state.priority = "P0"
    elif tier == "strategic" and "renewal" in summary:
        self.state.queue = "account_escalation"
    else:
        self.state.queue = "support"
    return self.state.queue
