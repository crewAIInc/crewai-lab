the conversational toolbox

New methods, one glance

handle_turn(msg, session_id=…)

One turn. Stores the message, runs the flow, returns the reply. The production entry point.

chat()

Local REPL. Terminal loop with prompts and exit commands; finalizes traces for you.

route_turn(context)

The router hook. Base = LLM router over docstrings. Overrides replace it — None means converse, not delegate; use super().

append_assistant_message()

Reply into history. Whatever handlers append is what the next turn's LLM sees.

state.current_user_message

This turn's line. Plus state.messages (history) and state.id (session).

finalize_session_traces()

Close the batch. With deferred tracing, call it in finally when you own the loop.

also ❯ stream_turn() RouterConfig (LLM routing) classify_intent() @persist (resume sessions) state.ended

which router, when

Programmatic route_turn vs the docstring catalog

override route_turn()

When a misroute is a policy problem. Permissions, compliance, exact signals (IDs, URLs, commands), zero-token routing, decisions you must be able to inspect and replay. Same input → same route, provably.

docstring router

When a misroute is just a wrong answer. Fuzzy natural-language intent, phrasing you can't enumerate, route sets that grow — the catalog maintains itself from handler docstrings, and failures fall back to converse.

hybrid — this module

Both, layered. Override for session setup and policy, then super().route_turn(ctx) for intent. Handlers still enforce permissions in code — the LLM only ever picks, never permits.

  • Gotcha: the base route_turn() IS the LLM router — overriding replaces it, and returning None means "no decision → converse", not "delegate".
  • Cost: programmatic routes are free; every catalog decision is one small LLM call.

Rule of thumb: if a misroute is a security problem, route in code. If it's just a wrong answer, let the model route.

05 / 07

built-in routes · llm routing

What you get for free

  • converse — the default route: the configured LLM answers with system prompt + full history. No handler needed.
  • end — sets state.ended; route goodbyes here to close the session cleanly.
  • answer_from_history — optional short-circuit that answers from existing history when answer_from_history_llm is set.
  • LLM routing: give @ConversationConfig a RouterConfig — the route catalog is auto-built from your @listen handlers' docstrings. Overriding route_turn() replaces the router; delegate explicitly with super().route_turn(ctx).

This module now delegates INTENT to the docstring catalog — but authorization still lives in code, enforced inside every handler.

sessions, persistence, traces

One session, many turns, one trace

owning the loop yourself
flow = PermissionedChatFlow()
session_id = str(uuid4())
try:
    flow.handle_turn("Research agent orchestration.", session_id=session_id)
    flow.handle_turn("Now fetch https://docs.crewai.com", session_id=session_id)
finally:
    flow.finalize_session_traces()   # deferred batch spans all turns
  • This module ships with @persist(): quit, rerun with the same --session id (or CHAT_SESSION), and the chat resumes — history intact.
  • Resume-safe claims: identity sticks to the session, but permissions are re-resolved every turn — a resumed session never keeps grants the profile has lost.
  • defer_trace_finalization=True keeps one trace batch open across turns — the finally closes it.
  • chat() (the REPL we demo with) handles all of this for you.
